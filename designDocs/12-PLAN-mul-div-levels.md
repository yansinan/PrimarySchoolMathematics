## 一、结论先行

乘除法在**生成器、求解器、统计映射**三层本来就完整支持，真正的断点在「题目 → 难度档位」的匹配：乘除题能算出、能存下，但 `matchLevel` 返回 `null`，导致进不了能力画像、进不了统计，还会被 `adaptiveBatch` 的 B12 校验当作非法题丢弃。

本轮按方案 A 打通了这条链路，新增 12 个乘除档位，**原有 12 级加减档位与逻辑一行未改**。

## 二、分级依据：人教版教材实际教学顺序

查自人教版电子课本（`www.dzkbw.com/books/rjb/shuxue/*`，2025 秋 / 2026 春修订版目录）：

| 学段 | 教材单元 | 内容 |
|------|---------|------|

| 二上 | 三、1~6 的表内除法 | 平均分、除法意义、用 2~6 口诀求商 |
| 二上 | 五、7~9 的表内乘、除法 | 7/8/9 口诀、用 7~9 口诀求商 |
| 二下 | 一、有余数的除法 | 有余数除法（本轮未做，见「已知限制」） |
| 三上 | 四、多位数乘一位数 | 口算 → 不进位 → 进位 → 连续进位 → 0 的乘法 → 中间/末尾有 0 → 估算 |
| 三下 | 二、除数是一位数的除法 | 口算除法、笔算除法 |
| 四上 | 三、多位数乘两位数 | 两位数×两位数、三位数×两位数 |

**分级维度选择「操作数位数」而非「是否进位」**，理由见下文「三、2」。

生成质量约束（第二轮调优补的）：

- 口诀档下限取 2，排除 `1×3` 这种无训练价值的题目
- 表内除法要求商 ≥2，排除 `4÷4=1`
- 两位数÷一位数要求商 ≥10（商两位数是该课时的教学目标），把 `21÷7=3` 这类表内题交还表内档
- 两位数÷两位数要求商 ≥2，排除 `80÷80=1`

四个判据（`opMin`/`opMax`/`quotMin`/`quotMax`）都只在 formulaList 项上存在时生效，加减档位没有这些字段，行为完全不变。

所有乘除档位 `operators` 用数字码 `[3]`（×）/ `[4]`（÷），与 `psm.js` 的 `symbols` 码一致；除法档位额外声明 `remainder: '2'`（整除）。

### 关键实现细节

1. **匹配不需要"运算符优先分流"**：`formulaList.operators` 是现有的运算符闸门，乘除档位写 `[3]`/`[4]` 后，加减题的匹配路径天然跳过它们（`hasExplicitOp` 为真且无匹配项 → `continue`）。原方案里设想的"先分组再匹配"是多余的，实际只加了可选判据。

2. **放弃"不进位/进位"细分**：`psm.js` 的乘法校验 `isMultDivOk` 不读 `carry`，生成侧无法约束是否进位 —— 细分出的两档会生成同一批题。故改为按「乘数位数」分级（生成器可按范围精确控制），这也是教材"多位数乘一位数"单元的天然分界。

3. **`remainder` 语义与直觉相反**（本轮最大坑）：
   - `psm.js:184` `remainder === 2` → **必须整除**（`a % b === 0`）
   - `psm.js:195` `remainder === 3` → **必须有余数**（`a % b > 0`）
   - 而 `adaptiveEngine.baseConfig.remainder` 默认是 `'3'`

   所以除法档位若不自带 `remainder: '2'`，生成的全是有余数题，再被 `Number.isInteger(solution)` 过滤，结果全是 `null` —— 最初除法档位"一道题都出不来"就是这个原因。

4. **`quotMax` 判据的必要性**：仅靠操作数范围无法区分 `24÷2=12`（商超表内）与 `24÷4=6`。表内除法档位加 `quotMax`（商上限）后，`24÷2` 正确落到「两位数÷一位数」。

5. **`_isMultCarry` 保留但当前不参与分档**：实现为竖式逐位模拟（位积 + 进位 ≥10），供未来做"进位"细分或错题归因使用；乘法档位的 `carry` 一律 `'1'`（不限制），避免误杀。

## 五、验证结果

- 单元测试：`npx vitest run` → **162 通过（原 120 + 新增 42），连续 3 轮全绿**，单轮约 20s
- 加减回归：`3+4=`、`9+8=`、`12-5=` 匹配结果与实施前完全一致；原有 120 个用例零失败
- 生成验证：12 个乘除档位各自生成 5 道题，全部含 ×/÷、解为正整数、`EquationSolver` 复核一致、`matchLevel` 反推在 ±1 档内（与引擎 B12 校验同标准）
- 整除验证：6 个除法档位各生成 5 道，全部 `a % b === 0`
- 匹配准确性：`12×3`、`27×4`、`105×3`、`23×14`、`456×23`、`12÷3`、`63÷7`、`84÷4`、`840÷4`、`96÷12`、`840÷12` 全部命中预期档位（见 `test/services/matchLevel.muldiv.spec.js`）
- 端到端（headless Chromium 驱动 http://127.0.0.1:4003，vite HMR 后的真实页面）：

  - 七个乘除档位各生成 6 题，**竖式出现次数全部为 0**（强制横式生效），算式全部含 ×/÷：

## 六、已知限制（未做，按需再开）

| # | 限制 | 影响 | 后续做法 |
|---|------|------|---------|
| L1 | 竖式布局不支持乘除 | 若练习进入 `vertical_keypad` 模式，乘除题排版会错 | 需改造 `VerticalLayout.vue`（部分积行 / 长除格式），或乘除档位强制横式 |
| L2 | 能力评估（诊断）仍只有加减 5 题 | 首次评估不会探测乘除水平 | `diagnostic.js` 加 L6/L7；`totalQuestions` 已动态，UI 无需改 |
| L3 | 有余数的除法未做 | 二下教材单元未覆盖 | `remainder:'3'` 可生成，但需要答题端支持"商+余数"双输入 |
| L4 | 阶梯是线性数组，升阶按 `difficultyIdx + 1` | 从「综合挑战」升到「乘法口诀·2~6」会一次跳到乘法，难度不连续 | 若需要跨运算符渐进，需在 `pickLevelForSlot` 加分段逻辑 |
| L5 | 含 0 的乘法（105×3、20×4）未单独成档 | 教材三上有专门课时 | 需 `hasZero` 判据 + 档位；当前归入「三位数×一位数」 |
| L6 | 混合填空（`__×3=12`）已有求解支持但未在乘除档位验证 | 低 | 加 `whereIsResult` 变体用例 |
