# 14 · 修复「口诀没练完就跳进多位数乘法」

> 状态：**已实施**（2026-11-19 起，§六~§八 补记至 2026-11-20）
> 触发：dr 反馈「在基础乘除口诀还没完成的情况下，突然进了多位数乘法」
> 选定方案：**B（修机制 + 自动回退）**，答题史/统计保留
> 最终验证：243 tests / 19 files 全通过（含 profileLadder / levelOverride / challengeEnabled / challengeSetting 新增用例）

---

## 一、结论先行

不是「多位数乘法档位生成错了」，而是**升档阶梯本身会跳档**：

`Profile.computeDifficultyIdx` 只用「答题命中的档位」当证据，而每轮练习会往
`difficultyIdx + 1`（挑战题，15%）和 `≤ difficultyIdx + 2`（强项题）混题。
这些跨档探针只有 3~6 道，答对就 100% 命中下一档，被当成「该档强项」→ 下一轮整体
跳档，全对时还会再 +1。

真实链路模拟（诊断 5 题全对 → 之后每轮 30 题全对）：

| 轮次 | 起始档位 | 本轮实际练习的档位分布 | 下一轮 |
|---|---|---|---|
| 诊断 | — | 加减 5 题 | 8 进退位巩固 |
| 第 1 轮 | 8 进退位巩固 | 加减 28 题 + **乘法口诀·2~6 仅 6 题** | **10 乘法口诀·7~9** |
| 第 2 轮 | 10 乘法口诀·7~9 | 口诀 14 题 + **表内除法·2~6 仅 3 题** | **12 表内除法·7~9** |
| 第 3 轮 | 12 表内除法·7~9 | 表内除法 11 题 + **大数加法仅 3 题** | **14 大数减法** |
| 第 4 轮 | 14 大数减法 | 大数加减 24 题 | **15 综合挑战** |
| 第 5 轮 | 15 综合挑战 | 大数加减 23 题 + **两位数×一位数 5 题** | **17 三位数×一位数** |

5 轮 ×30 题 = 150 题就从「二上两位数加减」窜到「三上多位数乘法」，
乘法口诀·2~6 / 表内除法·2~6 / 大数加法 各只有 3~6 道探针题，等于没练。

---

## 二、根因

1. **证据单元错了**：升档看的是「单道题命中的档位」，而不是「这一轮以哪一档起练」。
   挑战题天生就是 `+1` 档，于是它在下一轮的画像里就是「下一档强项」。
2. **没有题量门槛**：1 道题 100% 正确 = 该档「强项」，和练过 30 题等价。
3. **+1 叠加**：全部强项时再 +1，于是每轮实际跳 1~2 档，中间的档位被整段跳过。

> 同类 bug 在 13-PLAN §十一 修过一次（`matchLevel` 进位语义 + 诊断不跨运算类型推档），
> 这次是同一条链路的另一个入口：挑战题探针。

---

## 三、修复

### 改动 1：升档改成「按轮次走阶梯」（`services/abilityProfile.js`）

新增 `Profile.loadSessionLevels()`：从 `practiceSessions.profileSnapshot.difficultyIdx`
读出**每轮练习的起始档位**（同一 `practiceSessionId` 的多条记录只取第一条带快照的），
`computeDifficultyIdx(answers, sessionLevels)` 改为：

```
从最早的起始档位往上逐档检查：
  该档没有轮次记录（被判空档）    → 当前档 = 该档（回填重练）
  该档题量 < LEVEL_EVIDENCE_MIN  → 当前档 = 该档（中途退出不算练过）
  该档正确率 < 80%                → 当前档 = 该档（没掌握，继续练）
  三项都满足                      → 看下一档
```

结果：**每轮最多升一档**；跳过的档位下一轮自动回填。

### 改动 2：题量门槛常量（`constants/practice.js`）

`LEVEL_EVIDENCE_MIN = 10` —— 一轮至少答满 10 题才算该档「练过」，
判「掌握」的口径沿用引擎既有的 `ACCURACY_THRESHOLDS.good = 80%`（「答好一组」）。

### 改动 3：手动出题不参与阶梯（`composables/usePracticeSaver.js`）

只有 `listSource === 'adaptive'` 的轮次才写起始档位快照。
手动出题（Generate → 开始练习）照旧进答题史/统计，但不影响自适应升档。

### 没有改的部分

- `DIFFICULTY_LEVELS` 24 档、顺序、生成器、引擎三维调节、档位配比系数：一行未动
- 没有轮次记录时（首次诊断、旧数据）仍走原来的「诊断定位起点」逻辑（含不跨运算类型的 +1）
- 不改答题史：旧数据只作为「轮次标记」参与阶梯判定，统计/连续天数/错题本全部保留

## 六、补记（2026-11-19）：练习档位手动控制

> dr 试用后反馈：「设置里还是得加一个控制当前难度级别的按钮。现在情况是，我孩子的进度
> 已经跳到多位数乘法了，我也没法修改」。
> 这**推翻了 13-PLAN 里「档位是引擎的私事、不向用户暴露」的定调** —— 只保留自动升档，
> 一旦被历史数据带偏，家长没有任何手段纠正。现在把「起点档位」这一个旋钮交给家长。

### 1. 入口

`测试生成（右下角绿按钮）→ 其他设置 → 练习档位`（与「档位配比」同一抽屉）：

- **当前实际档位**：读 DB 画像实时显示（`Lv.N 档位名 [年级]`）
- **起点档位**：24 档下拉（按年级分组），清空 = 自动
- **应用起点档位** / **恢复自动** 两个按钮
- 文案明确「只改从哪一档开始练，不删答题史、不影响统计，下次开始练习时生效」

### 2. 语义（`utils/store/levelOverride.js` + `Profile.load`）

覆盖值 `{ levelIdx, since }` 存 localStorage（与档位配比/出题设置同层，属本机设置）：

- 有覆盖 → 自适应练习从 `levelIdx` 起；`since` 之前的旧轮次**不再参与升档阶梯**
  （否则旧数据会把孩子再次拉回高档位）
- 攻克一档后照常 +1，越过覆盖值后覆盖不再起钉住作用，但仍保留 `since` 过滤
- 清除覆盖 → 回到「按全部练习记录计算」（历史里练过的档位会重新算进去）
- `重置数据` 会一并清掉这个设置（`databaseInit.clearAllData`）

界面联动：`practiceStore.levelOverrideRevision` 版本号 → `Practice.vue` watch →
准备界面立即刷新档位，不需要刷新整页。

**练习重点同步收口**（dr 试用反馈：改完设置后「练习重点」还写着 `多位数×多位数`）：
`Profile#getFocusLevels()` 只取**当前档位及以下**的弱项并升序取前 3 个。
更高的档位这轮根本不会出题（出题上限是 `difficultyIdx + 2` 的强项池 + 挑战题），
显示成「重点」会误导；弱项全在当前档位之上时该区块直接隐藏。

### 3. 顺带修掉的一个匹配缺陷

验证时发现：答题记录里 `operator` 存的是归一化 ASCII（`*` / `/`），算式是显示符号
（`×` / `÷`）。`Question._parseOperands` 只按 ASCII 找运算符，找不到就返回 `[null, null]`
→ 这类记录 `matchLevel` 返回 `null`（旧数据 `operandMin/Max` 为 0 时会踩到）。
现在找不到时按显示符号再找一次（`*`→`×`，`/`→`÷`），并加了回归用例。

### 4. 验证

| 场景 | 结果 |
|---|---|
| 造一轮起始档位 18（两位数×两位数）的历史 → 准备界面 | `Lv.20 两位数÷一位数`（自动会推到 19 档） |
| 其他设置里选 `Lv.10 乘法口诀·2~6` → 应用 | 抽屉内「当前实际档位」立即变 `Lv.10`，出现「已手动指定」标记 |
| 关掉抽屉 | 准备界面**不刷新**就变成 `Lv.10 乘法口诀·2~6 [二上]` |
| 刷新页面 | 仍是 `Lv.10`（设置已落库 localStorage） |
| 开始练习 | stage = `乘法口诀·2~6 · 第1组`，首题 `2×2=`，`engineDifficultyIdx = 9` |
| 恢复自动 → 刷新 | 回到 `Lv.20 两位数÷一位数` |
| 单测 | **228 通过（17 文件）**，其中新增 `test/services/levelOverride.spec.js` 6 条 + 阶梯 baseline 3 条 |

### 5. 备注

- 设置在**浏览器本地**（localStorage）。孩子若在另一台设备/另一个浏览器练习，
  需要在那台设备上再设一次（本项目没有账号/云同步）。
- 「恢复自动」= 按全部答题史重算，因此历史里被 bug 跳档练过的档位会重新被算作「练过」，
  档位可能又回到高位 —— 想保留校正结果就不要点它。

## 七、混题上限收口（2026-11-20）

> dr 反馈：把起点档位钉到「乘法口诀·2~6」后，练习里「还是混到了不应该出现的高难度题目」。

定位（`Engine.pickWeakLevel` / `pickStrongLevel`）：

| 来源 | 原上限 | 问题 |
|---|---|---|
| 弱项题 `pickWeakLevel` | **没有上限** | 弱项列表来自全部答题史。孩子高档乘除错得多 → `weakLevelIndices=[16,18,19]`；钉在口诀·2~6 时，弱项题直接出「两位数×一位数」的高档题（实测一组 30 题里混进 9 道 16 档） |
| 强项题 `pickStrongLevel` | `difficultyIdx + 2` | 钉在口诀·2~6 时还能出到「表内除法·2~6」，比当前档高 2 档 |
| 挑战题 | `difficultyIdx + 1` | 合理，保留 |

修法（只动这两个上限，出题结构/配比不变）：

- `pickWeakLevel`：只取 **`<= difficultyIdx`** 的弱项（补弱不越级）；一个都没有就返回 `null`，
  由 `pickLevelForSlot` 退回当前档位，绝不硬塞高档错题
- `pickStrongLevel`：`MAX_ADVANCE` 2 → **1**，与挑战题同一个上限

效果：整组题目的档位上限 = `difficultyIdx + 1`（挑战/强项同高），不会再出现「跳 2 档以上」的题。

### 实测

| 场景 | 结果 |
|---|---|
| 造「8/10 档全对、16/18 档全错」历史 → 自动档位 Lv.19 | 练习重点 = 两位数×一位数 / 两位数×两位数 |
| 钉到 Lv.10 乘法口诀·2~6 → 开始练习 | `engineDifficultyIdx=9`，连答 8 题：`7×7 9×8 5×4 4×6 2×8 5×8 3×9`，**无一道超档**（9×8 属 +1 档挑战上限） |
| 单测 | **233 通过（17 文件）**，新增「整组不超过当前档 +1」与弱项上限用例 |

## 八、挑战题改为家长手动开关（2026-11-20）

> dr：「现在看挑战题确实应该手动选择，因为有些阶段，孩子没学到就不会，不是努力能解决的问题」。

挑战题 = 当前档位 + 1 档的题。原先每组固定约 15%，靠「探索边界」自动加难度；但遇到
孩子还没学到的单元（例如三上「多位数乘一位数」之前），出这类题只会挫败，不是努力能解决的。

改动：

| 项 | 原行为 | 现在 |
|---|---|---|
| 挑战题槽位 | 恒定 `difficultyIdx + 1` | **家长开关控制**：关 → 只出当前档；开 → `+1`（原行为） |
| 强项题上限 | `difficultyIdx + 2`（上一轮已收到 +1） | 关 → **当前档**；开 → `+1` |
| 默认值 | 自动开启 | **关闭**（只出当前档及以下） |

- 存储：`utils/store/challengeSetting.js`（localStorage `psm_challenge_enabled`，默认关）
- 开关位置：`其他设置 → 练习档位 → 挑战题（下一档）`，切换即生效（下一轮开始练习时）
- 准备界面「这次练什么」多一个 chip：`只练本档` / `含挑战题·下一档`
- `重置数据` 一并清除该设置

### 实测

| 检查点 | 结果 |
|---|---|
| 设置抽屉 | 开关存在、默认未选中 |
| 准备界面（默认） | chip = `只练本档` |
| 钉到 Lv.10 后开始练习 | `engine.challengeEnabled=false`、`difficultyIdx=9`，连答题目 `6×5 / 4×6 / 5×5` 全在本档 |
| 打开开关后 | localStorage=`1`、chip = `含挑战题·下一档`、`engine.challengeEnabled=true`、强项池可选到 10 档（+1） |
| 单测 | **243 通过（19 文件）**；新增 `challengeSetting.spec.js` 6 条、`challengeEnabled.spec.js` 4 条 |

> 注：关闭挑战题后，`evaluateGroup` 的组内升档逻辑不变（仍是 5 组 + 连续 3 组好评），
> 但跨轮升档只走「阶梯」这一条路 —— 因为不再有 `+1` 档的探针题去污染档位证据。
